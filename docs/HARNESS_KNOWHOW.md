## A. Dynamic Workflow

### A1. `args`가 문자열로 도착할 수 있다 — 스크립트에서 방어하라

**실측**: `Workflow`에 `args`를 JSON **객체**로 넘겼는데 스크립트에서
`args.templates[arm]`이 터졌다.

```
parallel[0] failed: undefined is not an object (evaluating 'args.templates[arm]')
   ... × 45 (전 bundle 동일)
agent_count: 0, duration: 77ms
```

진단의 resume 안내에 되돌아온 값이 `args: "{\"payloads\": ...}"` — **문자열**
이었다. 에이전트는 **한 건도 실행되지 않았다**(0/45, 77ms).

**함의**: `args`를 쓰는 스크립트는 첫 줄에서 정규화해야 한다.

```js
const A = typeof args === 'string' ? JSON.parse(args) : args
```

**교훈의 값**: 이 실패는 **비용이 거의 없었다**(77ms, 에이전트 0). 반대로
스크립트가 args를 관대하게 받았다면 45개 에이전트가 잘못된 프롬프트로
돌았을 것이다. **일찍 시끄럽게 죽는 게 이득인 자리다.**

### A2. args 대신 스크립트 파일에 데이터를 박는 것이 낫다

**실측**: A1 이후 Python으로 스크립트를 생성해 데이터를 `const DATA = {...}`로
**임베드**하고 `scriptPath`만 넘겼다 → **45/45 성공, 에이전트 오류 0.**

세 가지 이득이 실제로 나왔다:

| 이득 | 근거 |
|---|---|
| args 문자열/객체 모호성이 **사라진다** | A1의 실패 모드가 구조적으로 불가능 |
| 재시도 시 대용량 데이터를 **다시 안 보낸다** | 14KB × 3 청크를 재발신할 필요가 없었다 |
| 임베드 전에 **결정론 검증**을 걸 수 있다 | 아래 A3 |

### A3. 임베드 전에 재구성이 동결본과 바이트 일치하는지 검증하라

**실측**: 프롬프트 전문(45개)을 넘기는 대신 **arm별 템플릿 3개 + fixture별
payload 3개**로 분해해 넘겼다(14KB → 전체 45 trial 커버). 분해가 안전한지는
넘기기 **전에** 확인했다.

```
reconstruction matches frozen hash: 45 / 45 mismatch: []
```

`template.replace('{payload_json}', payload)`가 동결된
`rendered_prompt_sha256`과 45건 전부 일치. **검증 가능한 분해이지 추측이
아니다.** 이 검증 없이 분해했다면 45개 trial이 동결본과 다른 프롬프트로
돌았을 수 있고, 사후에는 알 수 없다.

### A4. `journal.jsonl`은 **에이전트의 반환값**을 기록한다 — `.then()` 매핑 결과가 아니다

**실측**: `agent(...).then(out => ({trial_id, raw: out}))`로 매핑했으나
journal에는 매핑 결과가 없다.

```
result keys: ['type', 'key', 'agentId', 'result']
key format: v2:0355ecf0f... (len 67)
result field type: str
trial_id in result field? False
```

- 레코드 타입은 `started` / `result` 두 종
- `key`는 **콘텐츠 해시**(`v2:<64 hex>`)이고 `opts.label`이 아니다
- `result`는 에이전트가 반환한 **문자열 원문**

**함의**: journal만으로는 **trial 정체를 복원할 수 없다.** 처음에 journal에서
`trial_id`를 찾다가 0건이 나왔다. 정체는 **워크플로의 반환값**에서 와야 한다.

### A5. 워크플로의 전체 반환값은 task 출력 파일에 있다 — 스크립트로 처리하라

**실측**: task 출력 파일 최상위 구조.

```
keys: ['summary', 'agentCount', 'logs', 'result', 'workflowProgress',
       'totalTokens', 'totalToolCalls']
result: list, len 45
```

`result`에 반환 배열이 그대로 있다. 이 파일을 **컨텍스트로 읽지 말고 스크립트로
처리**하면 45건 원문을 컨텍스트 폭발 없이 회수할 수 있다 — 45건 중 파싱
실패 0, 매니페스트 대조 누락 0.

알림에 온 반환값은 **66KB 지점에서 절단**돼 있었다. 원문이 필요한 작업(감사
가능한 기록)은 처음부터 이 경로를 계획해야 한다.

### A6. `label`은 표시용, 캐시 키는 콘텐츠 해시

A4의 `key` 형식이 그 증거다. resume 캐시는 `(prompt, opts)`가 같으면 적중하고,
`label`을 바꿔도 캐시는 유지된다 — 반대로 **`label`로 결과를 찾을 수는 없다.**

## B. 실험 하네스 설계

### B1. 사전등록 게이트를 규율이 아니라 **코드**로 강제하라

**실측**: `_h3.py`에 E2.3의 `preregistered_design_commit()` 패턴을 옮겼더니
실제로 나를 막았다.

```
PREREGISTRATION_REQUIRED: commit all H3 design files before freezing.
?? experiments/.../\_h3.py
```

freeze가 거부됐고, 설계 파일을 커밋한 뒤에야 통과했다. **"결과를 보기 전에
동결한다"를 사람의 기억에 맡기지 않는다.**

### B2. 타 실험의 상수 재사용은 import가 아니라 **AST 추출**로

**실측**: E2.3 `_gen_prompts.py`를 다른 디렉토리에서 로드하면 실패한다.

```
ModuleNotFoundError: No module named '_cert_core'
```

원인은 그 파일 40번 줄의 모듈 최상단 `from _cert_core import run_and_certify`
— 자기 디렉토리가 `sys.path`에 있을 때만 해석된다. 동결 규율상 실험마다
같은 모듈명을 중복 보유하므로 이 상황은 **구조적**이다.

**해법**: `ast.parse` 후 이름으로 최상단 대입을 찾아 `ast.literal_eval`.
상수 이름이 바뀌면 **시끄럽게 실패**하도록 예외를 던진다. 조용한 하드코딩
사본보다 낫다 — 사본은 원문이 바뀌어도 아무 일도 일어나지 않는다.

### B3. 앵커 기반 텍스트 추출은 **중복을 탐지하지 못한다** ⚠️

**이번 세션에서 가장 값비싼 교훈이다.**

앵커 추출은 잘 작동했다 — `contract_prompt.md`에서 규칙 1~7을 뽑고, 앵커가
없으면 `SurfaceError`로 실패한다. 문구가 바뀌면 조용히 옛 텍스트로 돌지 않는다.

**그런데 앵커는 "그 문장이 있는가"만 본다. "같은 의미가 다른 곳에 또 있는가"는
보지 않는다.**

H1a는 계약문에서 liveness 금지 문장 하나를 제거하는 조작을 설계했다. 실측:

| 위치 | 내용 |
|---|---|
| 서문 (block L8) | `모델은 출처의 liveness나 우선순위를 재판정하지 않는다.` |
| 절대 규칙 1 (block L24-25) | `어떤 출처가 더 최신인지, 더 권위 있는지, 아직 살아있는 코드인지를 추론하지 마라. 그 판정은 이미 끝났고 너의 범위가 아니다.` |

**둘째가 더 명시적이다.** 첫째만 지운 arm은 연구 대상 행동을 여전히 금지한다
→ **조작 무효.**

### B4. 가드가 통과하는데도 결함이 남을 수 있다 — 가드가 **무엇을 주장하는지** 보라

B3의 결함을 잡기로 설계된 가드가 있었다: "두 프롬프트가 정확히 그 한 문장의
유무로만 다름을 byte-level 테스트로 고정."

**그 테스트는 이 상황에서 통과한다.** diff가 실제로 그 한 문장이기 때문이다.
검사하는 명제가 *"diff가 지정된 문장인가"*이고, 필요한 명제는
*"어느 arm에도 동등한 금지가 남아 있지 않은가"*였다.

**일반화**: 가드의 **존재**를 근거로 쓰지 마라. 가드가 참으로 만드는 명제를
쓰고, 그 명제가 필요한 명제와 같은지 확인하라. 이 프로젝트에는 같은 형태의
선례가 있다 — `evidence_packet_schema.json`이 자기 `description`에
"hidden oracle fields must not be included"라 적어두고 **아무도 검사하지
않아** 네 fixture가 몇 주간 유출했다.

### B4a. 추가 (2026-08-05) — B4를 규율에서 **기제**로 옮겼다

B4의 일반화("두 명제를 적어 대조하라")는 **7회 처방되고 7회 실패했다**
(`docs/H1A_PROBLEM_ANALYSIS.md` P1 6건 + `_h1a_policy.py`의 `assert_5`).
규율은 매번 기억해야 성립하므로 실패율이 내려가지 않는다. 기제로 바꿨다.

**근본 이유 — 긍정 테스트로는 원리적으로 구별할 수 없다.**

| 가드의 실제 상태 | 정상입력 → pass? | 위반입력 → raise? |
|---|---|---|
| 정상 가드 | 통과 | 발동 |
| 공허한 가드 (no-op) | 통과 | **발동 안 함** |

긍정 테스트는 왼쪽 열만 본다. 두 행의 관측값이 같으므로 정보가 부족한 게
아니라 **측정 채널이 없다.** `assert_5`가 이 경로로 살아남았다.

**구현**: `test_guard_negative_coverage.py` (repo root). AST로
모듈 수준 `assert_*`/`_assert_*`를 수집하고, 본문에 `raise`/`assert`가 있는
것만 대상으로 삼아, `with pytest.raises(...)` 안에서 호출되지 않는 가드가
있으면 실패한다.

**왜 introspection이 아니라 AST인가**: import를 하지 않는다. 실험 폴더들이
동명 모듈을 중복 보유해 먼저 로드된 쪽이 `sys.modules`를 선점한다는
`pytest.ini`의 경고가 그대로 적용되기 때문이다. 파싱은 그 함정을 구조적으로
회피하고, 덕분에 `norecursedirs = experiments`에도 **root 테스트 1개가 실험
전체를 덮는다**. 배선 불필요 — core `pytest -q`가 이미 수집한다.

**검사기 자신도 양방향 테스트를 갖는다**(pattern 8). 스캐너의 recall
(긍정만 있는 가드를 잡는가) · precision(커버된 가드를 안 잡는가 / raise 없는
`assert_*` 리포터를 건드리지 않는가 / `policy.assert_x()` 속성 호출을 커버로
인정하는가)을 각각 고정했다. 그러지 않으면 recall 미지의 검사기를 만드는 셈이고
그건 이 파일이 막으려는 결함 그 자체다.

**실측 (2026-08-05)**:

| worktree | raising 가드 | 커버됨 | 미커버 |
|---|---|---|---|
| `concept-gate-owl-wt` | 10 | 9 | 1 → 닫음 |
| `concept-gate-h1-wt` | 18 | 16 | **2 (미해결)** |

owl의 1건(`_h1a_score.py::_assert_instrument_speaks`)은
`test_h1a_score_instrument.py`로 닫았다. **h1-wt의 2건은 열려 있다** —
`_assert_instrument_speaks`와
`_h1a_policy.py::assert_9_default_permission_is_byte_identical_across_arms`.
후자는 D-H1a-11의 12개 구조 단언 중 하나다. **본문을 읽고 나서 판정이
바뀌었다** — 공허하지는 않으나 **raise 경로 3개가 모두 도달 불가**다:
`render_policy_block`이 `GLOBAL_DEFAULT_PERMISSION_TEXT`를 모듈 상수에서
직접 읽어 양 arm에 무조건 방출하므로, "블록 개수 != 1"·"arm 간 불일치"·"상수
로부터 drift" 세 명제를 **코드가 구조적으로 참으로 만든다.** 발동시키려면
`render_policy_block` 자체를 모킹해야 하고, 그러면 모킹을 검증하는 셈이다.

즉 B4의 변종이다 — 가드가 참인 명제를 검사하는데 그 명제를 코드가 이미
보장한다. 다만 **처방이 다르다**: 음성 테스트를 쓰는 게 아니라 *"이 가드가
잉여인가, 아니면 renderer가 상수를 직접 읽지 않아야 하는가"*를 판정해야 한다.
설계 판정(Q12) 영역이므로 테스트가 대신 결정할 수 없다. **음성 테스트를
날조하지 마라** — 모킹 기반 음성 테스트는 게이트를 초록으로 만들면서 아무것도
증명하지 않는다.

그래서 게이트에 `KNOWN_UNPROVEN`을 뒀다: 이름 → 이유 + 담당. 예외가 이유보다
오래 살면 그것이 silent cap이므로 `test_known_unproven_entries_are_not_stale`이
(a) 그 이름의 가드가 사라지거나 (b) raise 능력을 잃거나 (c) 음성 테스트를
갖게 되면 실패한다. 예외 목록도 검사기이므로 **자기 음성 테스트를 갖는다**
(`test_the_staleness_check_itself_fires_on_a_bogus_entry`). owl 트리의 목록은
비어 있다(raising 10 / 커버 10).

적용 준비물은 검증돼 있다 — h1-wt에 이 파일 + `test_h1a_score_instrument.py`를
넣으면 raising 18 / 커버 17 / 문서화 예외 1 / skip 1 / **잔여 미커버 0**이다
(읽기 전용 시뮬레이션으로 실측).

**precision이 붕괴하지 않았다는 점이 이 게이트를 blocking으로 둘 근거다.**
`NEXT_SESSION_TRAPS.md` §3.2의 트립와이어 비용 교훈대로 먼저 실측했고,
18개 중 16개가 이미 통과했다 — 담요처럼 전부를 실패시키는 검사가 아니다.
비교: 같은 날 `SEARCH_DID_NOT_CONVERGE` 후보 2개는 144/144·92/92로 발동해
게이트 대신 disclosure로 내렸다.

**이 기제가 잡지 못하는 것 — 범위를 좁게 읽어라.** *존재하지만 증명되지 않은*
가드만 잡는다. **아예 없는 검사**는 찾을 `assert_*`가 없으므로 보이지 않는다.
`experiments/2026-08-04_owl_entailment_contract_shape/OPERATIONS_LOG.md`
2026-08-05 판정의 미포착 4건은 전부 그 두 번째 종류다. 이 게이트는 P1을 닫고,
그 4건은 닫지 않는다.

### B5. 제작자는 자기 산출물의 결함을 보지 못한다 — 리뷰를 분리하라

B3의 원문은 **제작 세션의 컨텍스트에 이미 있었다**(다른 작업 중
`contract_prompt.md` 전문을 판독했다). 그럼에도 발견되지 않았다.

발견한 것은 **별도 에이전트**였고, 지시에 두 조항이 있었다:

1. 제작자와 분리 — 제작자의 결론을 알려주지 않는다
2. **제작자의 테스트를 증거로 받지 말고 직접 재현하라**

두 번째가 결정적이었다. 리뷰어는 `diff -u`를 직접 돌려 사본 무결성을
확인했고, 파이프라인을 직접 실행해 반사실을 만들었다. 제작자 테스트를
믿었다면 B3·B4 모두 통과로 읽혔을 것이다.

### B6. 유효분모는 깨진 출력을 낸 arm을 **보상한다**

**실측**: H3 pilot에서 채점기의 `rate()`를 처음 유효 출력만 분모로 썼다.
그런데 arm별 invalid rate가 CONTRACT 0.20 / A 0.13 / CONTROL 0.00 —
**하필 실험 대상 arm이 가장 높았다.** 유효분모는 "틀린 답 대신 깨진 출력을
낸" 것을 보상하므로, 그 오류는 실험 대상을 유리하게 만들었을 것이다.

**해법**: 분모는 전체 시행. invalid를 별도 rate로 **병기**한다(둘 중 하나가
아니라 둘 다). 회귀 테스트로 고정했다.

### B7. 상수는 교란하지 않지만 **상호작용한다**

**실측**: "양 arm이 동일 fixture를 받으므로 앵커가 arm 대비를 교란하지 않는다"는
방어 논증을 썼다. 독립 리뷰가 반박했다 — 교란(confounding)에는 참이지만
**처치와의 상호작용**은 막지 못한다. 상수가 처치와 같은 방향을 가리키면 양
arm이 천장에 붙어 관측 차이가 ≈0이 되고, K=1이면 **ceiling-null과 진짜 null을
사후에 구별할 수 없다.**

"상수라서 안전하다"는 논증을 쓸 때는 **교란과 상호작용을 구별해서** 써야 한다.

### B8. 단일 스칼라 요약이 방향을 감출 수 있다

**실측**: H3의 1차 지표 Δ = P(defer|insufficient) 대비가 +0.80이었다.
"CONTRACT가 더 많이 보류한다"로 읽혔다. 외부 판정이 요구한 recall/precision
쌍으로 다시 재니:

| arm | recall | precision | defer 총수 |
|---|---|---|---|
| CONTROL | 0.00 | 0.00 | 3 (0 적중) |
| A | 0.00 | 0.00 | 4 (0 적중) |
| CONTRACT | 0.80 | **1.00** | 4 (전부 적중) |

**세 arm의 보류 총량은 3·4·4로 거의 같았다.** 차이는 양이 아니라 **조준**
이었다. 단일 대비는 그것을 담지 못한다.

## D. 하네스 재사용 형태 다섯 — 2026-08-31 세션 실측 (h1-wt)

한 세션에서 하네스 7종을 만들며 수정 라운드를 셌다. **가장 늦게 만든 둘**
(`scripts/session_snapshot.py` · `test_identifier_groups_sync.py`+생성기)이
**수정 1라운드**로 끝났고, 가장 먼저 만든 FQN 래칫은 **5라운드+**(경계 셋을
한쪽씩, 자기 주석에 5회 물림)였다. 차이는 실력이 아니라 **앞선 실패가 규칙이
된 뒤였는가**다. 그 규칙을 형태로 추출한다 — **재사용 단위는 코드+근거이지
코드만이 아니다**(근거 없이 베끼면 "왜 있는지 모르는 짝"부터 잘려나간다).

### D1. 열거 → 피복 → 잔여

출현을 **원문에서 전부 열거**하고, 구조는 각 출현을 **덮는** 데만 쓰고, 못 덮은
것을 **센다**. 구조에서 출현을 만들어 내면 규칙이 안 닿는 곳은 오분류가 아니라
**소실**된다 — 잔여 게이트가 영원히 초록(공허)이 된다.

근거: `identifier_scan` 1차가 계약 25개를 전부 통과하면서 `UNRESOLVED` 도달
불가였다(회고 2부 G249 경위). 동료 저장소 `test_scanner_residual.py` 도 동일 규율.

### D2. 래칫 + staleness 는 한 쌍이다

"증가 금지"만 있으면 면제 표가 낡은 채 남아 그 여유분만큼 새 위반이 조용히
통과한다. **감소하면 표를 줄이라고 강제하는 검사**가 반드시 짝으로 붙는다.

근거: `test_invariant_fqn_citation.py`(baseline 116) — SURVEY 가 34→33 으로 줄자
staleness 가 울었다(첫 실사례, G207). `test_guard_negative_coverage` 의

근거: `gen_identifier_groups` + `test_identifier_groups_sync`(양방향 음성 증명:

### D8. 측정기에는 대조군과 계수 분리를 내장한다 — 공허한 100% 방지

2026-09-01 실측(회고 4부 G269). 뮤테이션 측정기가 14/14 kill(100%)을
보고했는데 전부 **exec 실패를 kill 로 오인**한 것이었다. 동료 세션의 검증
질문 3개가 이 형태의 일반형이다: ① kill 과 실행오류를 **따로 세는가**
② "생존 0"과 "뮤턴트를 못 만듦"이 **구별되는가**(지점 열거가 조용히 줄면
분모가 접혀 100% 유지) ③ 분모를 **재계산할 수 있는가**.

측정기에 내장할 것 넷:

1. **무변이 대조군** — 변이 없이 돌려 0 빨강이어야 측정 시작(아니면 러너
   자신이 병든 것). 실측: 이 대조군이 픽스처 오염(변이가 모듈 dict 를
   오염)도 잡았다.
2. **실패 종류별 계수** — exec 실패는 kill 이 아니다. 출력에 "별도 계수"
   를 명기한다.
3. **열거 0 = 명시 실패** — 분모가 0 이면 100% 를 내지 말고 죽는다.
4. **내역 출력** — 지점별(연산자·행·죽인 계약)로 내서 사람이 분모를 대상
   원문에서 재도출할 수 있게 한다. 완전성은 증명 못 하므로 그 한계도 적는다.

수치는 산문에 적는 순간 낡기 시작한다(P4) — **수치의 정본은 측정기의 실행
출력**이고, docstring 의 숫자는 시점 기록(날짜·커밋)으로 격하한다.

### D9. 서명·스키마 필드는 검증부가 읽을 때만 존재한다

2026-09-01 실측(G270, D-38 구현 적대검증 blocker). profile commitment 를
서명 본체에 넣었는데 검증부가 읽지 않아서, 다른 계약에 commit 한 인증서와
미선언(None) 인증서가 전부 통과했다. 적대검증자의 정식화:

> **"서명 아래에 넣는 이유는 verifier 가 읽기 때문이다 — 읽지 않으면
> 필드는 주석과 같은 지위다."**

같은 파일에서 스키마 식별자를 두 번(v0→v1, v1→v2) 올리면서 두 번 다
"검증부는 지금 이 문자열을 대조하지 않는다"는 주석을 남겼었다 — **같은
주석을 세 번째로 쓰게 되면 그것이 대조를 넣으라는 신호다.** 검사를 붙이는
형태: 미일치 = 거부(fail-closed), **None/부재는 wildcard 가 아니다**(미선언이
모든 계약을 통과하면 필드가 닫으려던 우회가 형태만 바꿔 열린다). 검사를
켜면 발급자 쪽 미선언이 즉시 드러나므로 발급자 명시화를 같은 커밋에서 한다.

### D10. 원격 관측 하네스 — 오류의 종류가 판정 어휘다

2026-09-01 실측(배포 검증 사다리 (c), `render_cert_probe.py` 승격). 원격
표면(배포 서버)은 게이트가 닿지 않는 관측 경계다. 그 경계의 하네스 규율:

- **판정 어휘를 먼저 정한다** — DOWN(응답 없음) / OLD(도구는 있는데 신형
  계열 없음) / NEW / Unauthorized(fail-closed = 신형 신호). 게이트의
  PASS/FAIL/BLOCKED 3값과 같은 이유: 침묵·실패·미확인을 접으면 오진이 된다.
  실측: 배포 반영의 첫 증거는 성공 응답이 아니라 **오류의 종류가 바뀐 것**
  이었다(도구 0개 → Unauthorized).
- **게이트에 배선하지 않는다** — 네트워크 검사는 비-hermetic(서버가 자면
  게이트가 빨개짐)이라 게이트 신뢰를 무너뜨린다. MANUAL_TOOL 층: 부를 때
  결정론적으로 재고 수치의 정본은 실행 출력.
- **프로토콜 함정은 측정기 docstring 에 박는다** — 세션 재초기화·재시도·
  백오프·토큰은 환경변수. 실측 함정: 세션 생성 함수가 튜플을 반환하는데
  통째로 헤더에 넣으면 "Session not found" 가 나고 **그 오진은 재배포
  증상과 구별 불가**다(6라운드를 태웠다, P25). 폴링을 시작하기 전에
  측정기의 반환 계약부터 읽는다 — 기다림이 비쌀수록 오진의 비용이 커진다.

### D11. 재생성 루프의 수락 기준은 "폐기 안 됨"이 아니다

2026-09-01 실측(G272). 결정론 필터에 재생성(재시도)을 붙일 때, "폐기되지
않았다(kept)"를 수락으로 쓰면 생성자는 **검사 불가 부류로 위장하도록
보상받는다** — 같은 환각을 트레이스백·화살표 출력·셸 명령·생략부호로
포장하니 전부 판정 보류가 됐다(탐지기가 세탁기로 반전).

- 수락 기준은 **적극적 확인**(≥1 확인된 인용)으로 분리한다. 판정 보류
  (NOT_CHECKABLE)는 3값 어휘의 BLOCKED — 자동 허용이 아니고, 종단 상태는
  "사람이 읽거나 생성자에게 사유와 함께 되먹인다"이다.
- 그 확인의 **건전성 범위를 계약으로 못박는다** — 인용 실재 확인은 "이
  문자열이 이 파일에 있다"에 대해 건전하고 "이 주장이 참이다"에 대해서는
  아니다(코드를 정확히 인용한 거짓 해석이 통과함을 계약이 단언한다).
- 루프에는 명시적 retry 한도와 abstention 이 함께 온다 — 재생성은 시도
  횟수를 늘리는 장치이지 옳음을 만드는 장치가 아니다.

## C. 아직 1회 확인이라 승격 보류 (그러나 재발 감시)

### C-0. 통합 관찰 — 합리화는 미명시 계약의 공백을 채운다 (사용자 정식화, 2026-09-01)

하네스 문제와 M1 hidden-contract 문제가 같은 구조라는 관찰. 세 층에서
같은 기제가 실측됐다:

| 층 | 미명시 | 합리화 | 실측 |
|---|---|---|---|
| trial 모델 | 전역 type 일관성 | "다른 type 이어도 정당하다" | wrong_direction 55% (E2.2.1) |
| 위임 subagent | 반환 형식·범위 | 범위 이탈·원자료 소실·재구성 측정 | 구속 없는 위임에서만 사고 (§D5 근거) |
| 세션 자신 | 사다리 대응 검증 | 상위목적 과장 | G261 계열 3회 |

처방의 뼈대도 동일(계약 명시 + 기계 집행)하되, **집행 채널이 층마다
다르다**: 코드=타입/게이트 · 문서=FQN 래칫 · 위임=반환 계약+결정론 필터 ·
**reasoning=자연어 전역 불변조건**(A_ONLY 20/20 vs schema 0/20 — 사전
명시 층에서는 자연어가 구조 강제보다 강하다, D7 이 독립 재현). 하네스는
**사후 검출**, reasoning contract 는 **사전 명시** — 같은 문제의 두 반쪽이라
어느 한쪽으로 대체되지 않는다.

### C-외부 후보 — 동료 세션(gate-vacuity) 실측, 우리 저장소 관측 0~1회 (2026-09-01)

동료의 호혜 회신에서 받았다. 전건 근거(그쪽 file:line·커밋) 붙어 왔고,
우리 정본 결함 정정 1건(LEGACY_REGISTER 행 — 철회된 논거를 사유로 싣고
있던 것)은 재실측 후 즉시 반영했다. 아래는 **우리 저장소에서 재발이
관측되면** §D 로 승격한다.

1. **P-스위치** — 완전성 검사가 **설정 공간의 한 점에서만** 돈다. 열거를
   끄는 스위치가 있으면 잔여 계수기가 정상 동작하면서 전면 공허해진다
   (그쪽 실측: 축 선택 시 14게이트 중 11이 did_not_run 인데 hard_gate_pass
   True — failure_codes 비어 있지 않은데 통과라는 자기모순을 잡는 불변식이
   없었다). 처방: 기제를 끌 수 있는 스위치에는 **스위치 자체의 대조**
   (각 축이 꺼진 상태로 최소 1회 관측) + 일관성 불변식. 우리 쪽 점검 대상
   후보: `certify_relation_claims(profile=)` 축 — 계약이 두 profile 을
   변주하고 있어(D-38 계약) 현재는 덮임, 새 스위치 추가 시 재점검.
2. **P-관측창** — 게이트가 옳게 계산하는데 **실패가 일어나는 시점이
   관측창 밖**이다(그쪽 실측: 커밋된 추가만 보는 재발명 게이트 — 재발명은
   언제나 커밋 전에 일어나므로 "만들지 마라"를 못 하고 "되돌려라"만 한다).
   처방: 게이트를 만들 때 **"어제의 그 실패를 이 게이트가 잡았겠는가"를
   재현**한다 — D8 무변이 대조군이 "러너가 병들었나"를 묻듯 이것은
   "관측창이 사건을 포함하나"를 묻는다.
3. **P-정본강등** — 앵커가 **존재하지만 더 이상 권위가 아니다**. §B3(같은
   의미의 다른 위치)과 다른 축: 앵커 문장이 그 문서에 여전히 있는데 문서
   자체가 stub 으로 강등된 경우, 존재 검사는 전부 초록이다. **존재와
   정본임은 다른 사실.** 우리 쪽 유관 실측: D2(래칫+staleness)와
   REMOVED-실재-금지 게이트가 인접하나 "정본 강등" 축은 안 덮는다.
4. **D1 세분화: P-도달불가가드** — 가드가 옳고 배선됐는데 **그 분기에
   들어가는 입력을 환경상 만들 수 없다**(독을 넣어도 발동 불가). 처방:
   상태를 인공 구성하는 경로별 목격자.

   **경계 해소 (2026-09-01, 동료 왕복 2회차)** — "인공 구성이 언제 모킹
   세탁이 되는가"의 판정 기준 넷(동료 실측 — 같은 상태에 목격자 둘을 두고
   이음매를 대조한 사례에서 도출):

   ① **생산자·소비자는 한 쌍** — 상태를 소비하는 가드의 목격자(리터럴
      상태 주입)만 있으면 세탁. 그 상태를 실제 코드가 실제 원인에서
      만들어 낸다는 목격자가 짝으로 있어야 완성.
   ② **이음매는 시스템이 소유하지 않는 가장 바깥**(subprocess·FS·네트워크·
      시계)에서 자른다. 측정형: **우회된 자기 함수 개수** — 0이면 픽스처,
      1 이상이면 그만큼 증명 범위가 좁아진 것이고 문서에 그렇게 적는다.
   ③ **현실의 원인을 이름 붙일 수 있어야** 한다 — 못 붙이는 분기는
      목격자를 붙일 게 아니라 지운다.
   ④ **조작이 오라클에 닿으면 항진명제** — 독이 기대값도 같이 키우면
      상쇄되어 조용하다(assert_9 자기동일성과 같은 형태, 동료도 자기
      실패 사례로 독립 재현).

   우리 `KNOWN_UNPROVEN` 규약과의 정확한 관계(원문 대조 완료): 우리 규약은
   A형을 금지하는 것이 아니라 **모킹 기반 음성 테스트를 증명으로 세는 것**을
   금지하고, 정직하게 못 쓰면 이유·담당을 등재하라고 한다 — 등재는 영구
   주차가 아니다(staleness 게이트 + assert_9 폐쇄 선례: "판정이 영구
   KNOWN_UNPROVEN 지위를 금지했다"). 즉 위 기준 넷은 우리 규약의 미정의
   부사 **"정직하게"의 조작적 정의**다.

   **그리고 이 기준이 우리 게이트의 맹점 둘을 드러냈다(둘 다 우리 저장소
   실측, 왕복 2~3회차)**:

   - **A형 계수**: `test_guard_negative_coverage.py` 는 "가드명이
     `pytest.raises` 안에 등장"만 보므로 소비자만 보는 목격자도 커버리지로
     센다 — 기준 ① 위반이 비가시.
   - **반환형 가드 비대상**(동료 가설 → 우리 실측 확인): 수집 규칙이
     `assert_*` 이름 + `raise`/`assert` 본문이라, **문제를 리스트로
     반환하는 가드는 아예 대상에 없다.** 실측: `validate_result`(위반
     리스트 반환 — 불변식 FQN 검사의 본체) 미수집, 이름 패턴 상한 census
     15건(단 상한이다 — `format_errors` 처럼 가드가 아닌 것과
     `validate_result` 처럼 목격자가 이미 있는 것이 섞여 있고, 진짜 구멍
     수는 반환형 수집기를 만들기 전까지 모른다). 동료 저장소도 같은 형태
     (29건 상한, 그쪽 §G 부채 등재) — **잘못된 baseline 위의 래칫은
     없느니만 못하므로(D2) 반환형 수집기가 래칫보다 먼저**라는 판단을
     양쪽이 독립적으로 내렸다.

   게이트 확장(생산자 짝 요구 + 반환형 수집)은 새 래칫이라 별도 판단.
5. **D8 반례 — 계수 정상이어도 인과 귀속은 별개**: 그쪽이 이상치(62/63)를
   고아 게이트 탓으로 귀속했다가 3가지 방법으로 재현 실패 후 철회. D8 의
   넷을 다 갖춰도 **이상치의 원인 설명은 별도 검증 대상**이다. 처방:
   측정기에 journal 을 붙인다 — 동료 설계(왕복 2회차): 뮤턴트마다
   `(op, file, line, killed_by, control_before, control_after, restored_ok)`
   한 줄, **무변이 대조를 같은 실행 안에서 앞뒤 두 번** 돌려 둘이 갈리면
   측정 중 환경 변화(오염·캐시)와 뮤턴트 특성이 사후에 갈린다.
6. **P-자기배반 가드** (동료 실측, 왕복 4회차 — 우리 census 0건 + 판별자
   정련): **비는 것이 목표인 목록에 "비면 실패" 단언을 걸면 그 목격자
   자신이 폐쇄를 막는다**(동료 실사례: 면제 목록의 음성 목격자가 실재
   항목을 요구 → 마지막 면제를 해소하는 순간 시험이 깨짐 — 압력이 없던
   게 아니라 **반대 방향** 압력). 처방: 규칙과 목록 분리 — 음성 목격자는
   합성 집합으로 규칙을 증명하고, 살아 있는 목록은 staleness 가 따로 보며,
   **폐쇄 가능성 자체의 목격자**(목록이 비어도 되는가)를 신설.

   **판별자(왕복 4~5회차에 양쪽 교차 검증으로 확정, 3행 + 판정 순서)**:

   | 종류 | 비면 | 비어있지-않음 단언 | 검증 데이터 |
   |---|---|---|---|
   | 해소 목표형 (면제·부채·미증명) | 성공 | **자기배반** | 동료 실사례(수리 완료) |
   | 영구 기록형 (죽은 도구 명부) | 게이트 공허 | 방어 | 우리 `test_legacy_register` |
   | 도출값 하한 (기계 파생의 바닥) | **도출 실패** | 방어 | 우리 4건(refs≥50·outbound≥10·manifests≥4·own≥60) + 동료 1건 |

   판정 순서(동료 정식화): **① 사람이 채우나 기계가 도출하나 — 도출이면
   즉시 방어**(비는 것은 정책 달성이 아니라 측정기 고장). **② 사람이
   채우면 그때 "비는 것이 성공인가"를 묻는다.** KNOWN_UNPROVEN 이 빈
   dict 까지 갈 수 있었던 것도 비어있지-않음 단언이 없었기 때문(게이트는
   빈 목록 위에서 정상 동작).

   census 의 부산물 1건: `test_wikilink_graph` 안에서 스캐너 산출을 계산해
   놓고 `>= 0` 을 단언하는 **항상-참 죽은 줄**을 발견·삭제했다 — 이 왕복
   전체의 주제(검사처럼 보이는 비검사)의 미시 실물.

   미검증 아이디어(동료, 명시적 표기): pytest.raises 블록 안에서 걸러
   버리는 비-가드 호출명들이 곧 기준 ②(우회 함수 수)의 공짜 근사치일 수
   있다 — 수집기 확장 시 확인.

7. **판정 채널 3종** (동료 어휘 제안, 반환형 수집기 공용 어휘로 채택):
   가드의 판정 채널은 `raise` · **반환값**(문제 리스트·`valid: False`) ·
   **상태 필드**(`_state: did_not_run` 류 3값)의 셋이다. 셋째의 우리 실물:
   `cg_fixture_resolver` 의 `execution="unavailable"`(ERROR 아님 — 부재와
   실패를 가르는 그 축), 게이트 러너의 BLOCKED. 수집기를 만들 때 셋을
   전부 세지 않으면 채널 하나가 통째로 사각이 된다 — 지금 우리 게이트는
   첫째만 센다(맹점 2호가 그 실측).

8. **D9 역효과 — "적었으니 됐다"**: does_not_measure/한계 목록에 적는 것이
