## (5)(6)(7) 상세 — 반복 O + 해결 근거 O

### A. P23 9·10회차 — "고쳤다"의 빈틈이 다음 회차에 드러난다 (**해결**)

**(5) 문제 정의.** 같은 규율을 세 번 고쳤고 매번 **고친 다음 회차에 그 수정의
빈틈**이 드러났다.

```
G208·G212  게이트를 안 돌리고 커밋          → 같은 블록에 둔다
G220       같은 블록인데 조건화 안 함        → && 로 조건화한다
G231       게이트만 조건화, 생성은 방치      → 모든 단계를 && 로 잇는다
```

**(6) 가설과 검증.**

- H1: 의지 문제 → **기각.** 첫 위반을 회고에 적고 곧바로 재발했다.
- H2: **수정의 범위가 좁다.** 매번 관측된 실패 하나만 막았고 **같은 계열의 인접
  실패**는 열려 있었다 → **채택.** 세 사례가 모두 "직전 수정의 옆"이다.
- 검증: H2 가 맞다면 **수정할 때 그 계열의 나머지를 함께 물어야** 재발이 멈춘다.
  G231 수정에서 "게이트만이 아니라 **한 블록 안의 모든 단계**"로 넓혔고, 이후
  커밋에서 재발하지 않았다(관측 구간 짧음 — 확정 아님).

**(7) 해결 방법.** CLAUDE.md §Git:

> **게이트 실행과 `git commit` 은 같은 명령 블록에 두고, 커밋을 게이트 결과에
> `&&` 로 조건화한다.** … **문서를 생성하는 단계도 `&&` 로 잇는다.** 게이트만
> 조건화하면 **게이트가 보지 않는 실패**가 통과한다.

### B. P25 22회차 — 고치는 문장이 다시 틀렸다 (**해결**)

**(5) 문제 정의.** HANDOFF ledger 의 시각 열에 **파일 mtime** 을 적은 것을 발견해
고쳤는데, 그 정정문에 **"01:42 는 9시간 뒤 첫 편집"** 이라 적었다. 그것도 틀렸다 —
기록은 UTC(`16:49:09Z`), mtime 은 로컬(KST `01:42`)이고 **실제 차이는 7분**이다.
손으로 적은 값이 거의 맞았고 **내 비교가 시간대를 섞었다.**

**(6) 가설과 검증.**

- 가설: 단위가 다른 두 값을 비교하면 그 차이는 **단위 차이**를 잰다 → 검증함.
  `2026-08-30T16:49:09Z` 를 KST 로 변환하니 `2026-08-31 01:49:09` 이고 mtime
  `01:42` 와 7분 차다.
- 이것이 minor 로 보고된 것도 검증 대상이었다 — 적대검증자는 "지금은 안전, 미래
  위험"으로 보았으나 **이미 나간 커밋의 문장이 그것 때문에 거짓**이었으므로 실제
  등급은 blocker 였다. **재실측 없이 severity 를 받았으면 정정하지 못했다.**

**(7) 해결 방법.** `Boundary` 에 `local` 필드를 더해 **UTC·로컬 둘 다** 낸다. 표에
두 열로 나온다. 그리고 **못 읽으면 빈칸** — 시간대는 지어낼 수 있는 종류의 값이
아니다. `test_utc_and_local_are_both_reported` ·
`test_an_unparsable_timestamp_yields_no_guessed_local`.

### C. G250·G253 — 층이 뒤집힌 것을 배포 결함이 드러냈다 (**해결**)

**(5) 문제 정의.** `INVARIANT_GROUPS = _invariant_groups_from_register()` 가 import
시점에 `docs/IDENTIFIER_REGISTER.md` 를 파싱했다. 배포에서 무력한 것이 문제로
보였으나, **실제 결함은 층의 역전**이다 — production 모듈이 사람이 유지하는
마크다운에 의존한다. 실측: `docs/` 를 여는 production 모듈은 그것 하나뿐이었다.

**(6) 가설과 검증.**

- 가설: 배포 결함은 **드러낸 것**이지 만든 것이 아니다 → 검증함. 로컬에 `docs/` 가
  있어 가려져 있었고, 표 형식이 바뀌면 **production 이 깨지는** 구조였다.
- 내 계약이 부정확했다는 것도 확인했다 — "등록부에서 **도출**"이라 썼고 구현자는
  합리적으로 "런타임 파싱"으로 읽었다. 의도는 **단일 출처**였다.

**(7) 해결 방법.** 생성물 + 일치 게이트. `scripts/gen_identifier_groups.py` →
`conceptgate/_identifier_groups.py`, 일치는 `test_identifier_groups_sync.py`(10개).
`Dockerfile` 은 **안 고쳤다**(`COPY conceptgate/` 가 통째로 넣는다 — 조사 회신의
"Dockerfile 수정" 제안을 재실측으로 기각).

그리고 **`INVARIANT_REGISTER_UNAVAILABLE` 을 지웠다** — 런타임에 등록부를 안 읽으니
그 상태가 존재하지 않는다. 계약이 미리 "이 게이트가 성공하면 사라질 것"이라 적어
뒀고 그대로 됐다. **지운 자리에 왜 있었고 왜 사라졌는지를 남겼다.**

### D. G261 — 층1의 해법은 층2로 전이되지 않는다 (**해결 — 조사로**)

**(5) 문제 정의.** 나는 "FQN 작업 → 판정이 불변식 지목 → Verify 신뢰 →
Semantic Compilation" 사다리를 세웠다. 사용자가 그 직접성을 의심했다.

**(6) 가설과 검증.** 두 그래프의 노드·간선·동일성 기제를 실측했다.

| | 층1 문서 그래프 | 층2 Semantic Graph |
|---|---|---|
| 노드 | 문서·절 | 개념·claim·formula |
| 간선 | cites · links_to · supersedes | is-a · has-a · anchored-in |
| **동일성** | **FQN** — 사람이 붙인 이름 | **fingerprint** — 내용에서 계산한 sha256 |

**층2 는 사람이 붙인 이름을 쓰지 않는다.** 그래서 FQN 을 정돈해도 층2 그래프는 한
노드도 안 생기고 한 간선도 안 정확해진다.

그리고 층1 결함의 층2 대응물이 **이미 막혀 있는지** 조사했다(코드 축·문서 축 분할):

```

① 같은 fingerprint, 다른 뜻 (충돌)     음성 증명 4건

코드에도 명시                          cg_identity.py:22 "같다는 뜻이지 참이라는 뜻이 아니다"
```

**(7) 해결 방법 — 사다리 수정.** `ObligationResult.invariant` 는 **검증 장치의
감사 가능성**(provenance)이고 **층2 그래프의 충실도**(fidelity)가 아니다. 회고에
그렇게 적어 사다리의 과장을 정정한다.

그 테스트가 성립하지 않는다. **More READ 없이 회고에 "빈 곳"이라 적었으면 그것도
추측이었다.**

## 위임 하네스 — 형식은 지켜졌고, "무엇을 볼지"는 안 지켜졌다

1부에서 성문화한 네 블록(원자료·범위 자기보고·잔여·근거 분리)을 이번 구간 조사

재발하지 않았다. 그런데 내용에서 셋이 어긋났다.

| 어긋남 | 실물 | 처방 |
|---|---|---|
| **구현 부재를 결함으로 보고** | 지적 10건 중 8건이 "구현이 없다"(TDD 빨강) | "그 부재를 결함으로 보고하지 마라"를 넣었다 |
| **없는 것을 지어내 재기** | 생성기가 없어 **scratchpad 에 재구성**하고 그 결함을 보고 | "실물이 없으면 지어내지 말고 잔여로 보고하라"를 넣었다 |
| **자기 셸을 재고 게이트라 보고** | `sys.executable` 이 게이트 하에서는 venv python 인데 자기 프로세스를 쟀다 | 위와 같은 문장이 덮는다 |

**하네스는 형식은 강제하지만 무엇을 볼지까지 강제하지 않는다.** 그리고 `(D) 추론

## 권한·도구·Context 차이 — 세 층으로 갈린다

1부는 이것을 다섯 축으로 적었다. 이번 구간에 **같은 세션 안의 시점 차이**를
실제로 겪어 세 층으로 나눈다.

### (가) Codex 와 Claude

동료 저장소의 `C-P7`(permission-lane conflation) · `C-P8`(읽기 전 추정) ·
`C-P10`~`C-P14` 는 **Codex 세션 계열**이고 `C-` 접두로 분리 발행돼 있다. 문서
frontmatter 가 `scope: current-codex-session` 으로 발행 주체를 스스로 밝힌다.

**우리 계열에 `C-P7` 대응물이 없는 것은 잘해서가 아니라 그 실패 경로가 없어서다.**
권한 구조가 다르면 겪는 이슈 자체가 다르다 — **그러므로 패턴 누계를 세션 간에
합산하면 안 된다.** 분모가 다르다.

그리고 `C-` 접두는 **우리 FQN 의 선행 사례**다. 우리가 `directive:I3` 로 도달한
곳에 그쪽은 먼저 도착해 있었다.

### (나) 세션 간

동료 세션과 5회 왕복하며 **양쪽 다 자기 workspace 만 재고 상대에 대한 결론을
냈다.** `P4` 논쟁이 그것이다 — 그쪽은 자기 저장소에서 우리 표현이 0건임을 근거로
"공유"라 했고(당연히 0건이다, 우리 정의니까), 나는 그쪽 정의를 **회신에서 읽고**
판단했지 그쪽 저장소를 열지 않았다.

**해소 절차가 확립됐다**: `파일:행` 교환 → **각자 상대 것을 직접 열기** → 그다음
판정. 그렇게 하니 그쪽이 우리 `:86`·`:537` 을 열고 "충돌 맞다"를 확인했고, 나도
그쪽 `:116`·`:168`·`:218` 을 열어 확인했다.

**이름공간이 진짜 결함이었다**(그쪽 진단). 그쪽 P 번호 9개가 우리 것과 전부 겹치고
28 미만에 빈 번호가 없다 — **번호를 옮기는 어떤 수도 못 고친다.** 처방은 저장소를
건널 때 접두를 붙이는 것이고, 표기는 **콜론형**으로 통일했다(하이픈형은 우리가
오늘 폐기한 것).

### (다) 같은 세션 안의 시점 차이 — **이번 구간의 신규 관찰**

**① 시점에 따른 workspace 차이.** `tool-calling-harnesses` 가 세션 중
`~/Downloads/` → `~/Desktop/` 로 **이동**했다. 사용자가 알려줘서 알았다 — 알려주지
않았으면 "경로 없음"을 "그 자료가 없다"로 읽었을 것이다. **경로는 작업 중 변한다.**

그리고 `.vault-harness` 가 **심볼릭 링크**임을 이번 구간에 알았다(`find` 가 링크를
안 따라가 "py 0개"로 보였다). 같은 트리를 두 경로가 가리키고 있었다.

**② 시점에 따른 context 차이.** compaction 이 12회 있었고 그 경계를 **도구로 뽑을
수 있음**을 이번 구간에 알았다(`subtype: compact_boundary`). 1부에서 손으로 적은
ledger 는 세 가지가 틀렸다 — 시각 열에 mtime, 횟수를 "여러 회"로 지어냄, 12건 중
3건만. **시점은 기억할 것이 아니라 잴 것이었다.**

**③ 시점에 따른 권한 차이.** 승인이 구간 중 **네 번 늘었다** —
`tool-calling-harnesses` 열람 · ① pre_compact · B · (b) 생성물 전환. 그리고 G252 는
"승인 범위 밖"이라 멈췄다가 나중에 승인되어 재개됐다.

**그러므로 "이 세션은 X를 할 수 있다"는 시점을 붙이지 않으면 거짓이 된다.** 회고를
읽는 쪽은 "왜 이것을 안 했나"를 물을 때 **그 시점의 권한**을 봐야 한다.

## 이 회고가 남기는 방법론적 사실

1. **사다리는 검증 대상이다.** 내가 세운 "FQN → … → Semantic Compilation" 이
   과장이었고, 사용자가 그 직접성을 물어서 드러났다. **상위목적으로 정당화하는
   습관은 정당화가 검증되지 않으면 합리화가 된다.**
2. **정본과 사본이 있으면 일치를 게이트가 강제해야 하고, 사본은 생성물이어야
   한다.** 손으로 유지하는 사본은 낡고(P4), 손으로 옮기면 전사 오류가 난다(P23 13회차).
3. **못 읽은 것을 "없다"로 말하지 않는다.** 이번 구간에 그 형태가 셋이었다 —
   등록부 미확인 대 문서군 부재 · 생성기 실패 대 빈 상수 · 시간대 미해석 대 빈칸.
   전임 도구가 제거된 사유가 같은 것이다.
4. **수정의 범위가 좁으면 다음 실패는 그 옆에서 난다.** 같은 규율을 세 번 고쳤고
   매번 직전 수정의 인접 빈틈이었다(P23 9→10, P27).
5. **층이 다르면 해법이 전이되지 않는다.** 층1 은 이름으로, 층2 는 해시로 동일성을
   정한다. 층1 에서 겪은 고통은 **층2 가 이미 회피한 문제**이고, 그래서 층1 의
   규율(이름공간·정본-사본 일치)이 층2 로 갈 자리가 없다.

## 방법론적 사실 (2부 목록에 추가)

6. **캐시는 디스크 사용량의 정상 상태다.** "회수 가능"은 삭제 직후를 잰 것이고,

8. **외부 세션의 자기 결함 공유가 우리 결함을 찾았다** — 두 번(빈 셀 ← 그쪽
