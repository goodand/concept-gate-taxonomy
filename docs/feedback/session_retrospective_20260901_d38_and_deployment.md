### G269 — 뮤테이션 측정기의 공허한 100% (P25 재발이자 신규 하위형)

- **(5) 문제정의**: 1차 뮤테이션 러너가 14/14 kill(100%)을 보고했는데, 검산하니
  **14건 전부 exec 실패를 kill 로 오인**한 것이었다. 통파일 exec 가 dataclass
  에서 죽었고(모듈 미등록 상태의 `sys.modules` 참조), 러너는 "테스트가
  빨갛다"와 "뮤턴트가 안 만들어졌다"를 같은 칸에 셌다.
- **(6) 가설·검증**: 가설 "100% 는 참이다" → 검산(내역 분해)으로 기각.
  동료 세션이 뒤이어 같은 형태를 독립 지적("21/21 이 앞서 공허했던 14/14 와
  형태가 같다 — 분모가 조용히 접히면 100% 가 유지된다").
- **(7) 해결방법**: 러너 v2 — 대상 함수만 추출해 실제 모듈 전역 위에서 exec
  (클래스 동일성 유지), **무변이 대조군 내장**(0 빨강이어야 측정 시작),
  exec 실패 별도 계수("kill 로 세지 않음"을 출력에 명기), 열거 0 이면 명시
  실패, 연산자별 지점 내역 출력(사람이 분모를 재도출 가능하게).
- **(4) 해결유무**: 해결. 최종 33/33, 생존자 1이 계약 1개를 낳음(any→all).
  측정기는 `scripts/mutation_two_pass_verify1.py` 로 승격.
- **(3) 해결근거**: `test_two_pass_verify1.py` docstring 뮤테이션 절,
  커밋 `3999d1e`·`eae3750`.

### G276 — 지시가 실행 환경을 건너며 뜻이 바뀜 (`!` 접두)

- **(5)**: 사용자에게 `! cd ... && ...` 형태 명령을 드렸는데, `!` 는 Claude
  Code 입력창 문법이고 **일반 zsh 에서는 부정 연산자** — `cd` 성공이 실패로
  뒤집혀 `&&` 뒤가 전부 무실행. 출력이 없어 실행된 것처럼 보였다.
- **(6)**: 원격 ref 불변 + 로컬 트리 clean + 커밋 부재의 3중 실측으로
  "무실행"을 확정한 뒤, zsh `!` 의미론으로 역산.
- **(7)**: `!` 없는 명령으로 재발급 + **받는 쪽의 셸을 명시**. 일반화:
  사람에게 건네는 명령은 그 사람의 실행 환경 문법으로 쓴다 — 세션 문법을
  누출하지 않는다.
- **(4)**: 해결(재실행으로 push 완료).

## 3. 이 구간의 구조적 관찰 — 검증 주체의 분업이 실측으로 갈렸다

같은 산출물을 네 주체가 각자 다른 것을 잡았다(전건 이 구간 실측):

| 주체 | 잡은 것 | 못 잡은 것 |
|---|---|---|
| 자작 게이트(결정론) | 규약 위반 8회(G275) — 커밋 전 | 산문의 참·서명 필드의 미사용 |
| 뮤테이션 측정기 | 계약의 빈 곳 1(any→all) | **코드를 안 바꿔도 이미 틀린 것**(공허한 PASS 류) |
| 적대검증(위임 LLM) | blocker 2(G270) — "읽지 않는 필드" | 자기 자신의 재구성 오류(다른 함수를 봄 — lead 재실측이 기각) |
| 동료 세션 | 산문 지시대상 오류(MAJOR 3, 직전 구간)·측정 형태 반복 지적 | — |

교훈의 형태: **각 검증층은 자기가 못 보는 부류를 갖고, 그 부류는 겹치지
않는다.** "검증자를 늘리는 것이 시야를 늘리지 않는다"(1부)의 보완 —
늘려야 하는 것은 수가 아니라 **근거 축**이고, 이 구간은 그 축들이 실제로
서로 다른 결함을 잡는 것을 처음으로 한 사이클 안에서 관측했다.
