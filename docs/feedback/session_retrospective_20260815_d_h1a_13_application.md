## (5)(6)(7) 상세 — 반복 O + 해결근거 O

### A. I23 — 정책 모듈 이중 로드 (P1 10번째, **이번에 해결**)

**(5) 문제 정의**: `_h1a_contract._fill_policy_slots`가 `_h1a_policy.py`를
`sys.modules["_h1a_contract__policy"]`라는 **사설 키로 두 번째 로드**하고
캐싱했다. 이 폴더의 로딩 규율은 "모든 호출자가 자기 키로 로드"이므로,
테스트가 규율대로 자기 사본을 만들어 변조하면 **세 번째 객체**가 생긴다.

```
프롬프트 바이트를 만드는 객체        <- 사본 B (_fill_policy_slots의 캐시)
테스트가 변조하는 객체               <- 사본 C (테스트의 키)
단언·연역검사가 읽는 객체            <- 사본 A
셋이 일치한다는 검사                 = 없음
```

**결과**: "policy를 변조하고 렌더된 프롬프트가 바뀌는지 본다" 형태의 모든
뮤테이션-리콜 테스트가 **원리상** 모델 대면 바이트의 결함을 탐지할 수 없었다.

**(6) 가설/검증**: 리뷰어 주장을 그대로 받지 않고 두 방향으로 실측했다.

```python
policy.render_policy_block = poisoned   # canary 문자열 주입
contract.render_arm(t, arm, policy_module=policy)  -> canary 있음  (True)
contract.render_arm(t, arm)                        -> canary 없음  (True)
```

두 번째 단언이 중요하다 — 주입이 반영되는 것만 확인하면 "기본 경로가 여전히
격리돼 있는가"는 미검증으로 남는다.

**(7) 해결 방법**: `_fill_policy_slots(template, arm, policy_module=None)` /
`render_arm(template, arm, policy_module=None)`. 기본값 `None`은 기존 동작
그대로(사설 캐시 로드)라 **모든 프로덕션 호출부는 무변경**이고, 뮤테이션을
증명해야 하는 테스트만 자기 모듈을 명시적으로 넘긴다. 넘기는 행위 자체가
"이 단언은 내가 변조한 그 객체에 관한 것"을 문장으로 만든다.

### B. I28 — 채점기에 fail-close 부재 (P-배선 계열, **이번에 해결**)

**(5) 문제 정의**: `_h1a_cohort.freeze()`는 보존 코호트 매니페스트 덮어쓰기를
거부하는데, **하네스의 반대쪽 절반인 `_h1a_score.py::main()`에는 동등한
가드가 없었다.** 무조건 `trials.json`·`h1a_cohort_score.json`을 쓴다 —
`COHORT_STATUS_20260803_nonidentifying.md`가 sha256을 기대고 있는 바로 그
파일들이다. 채점기를 어떤 이유로든 다시 돌리면 비가역 파괴.

**(6) 가설/검증**: **합성 fixture가 아니라 실제 저장소 상태**로 검사했다 —
두 파일이 지금 실제로 존재하므로 그대로 `main()`을 호출해 거부 발동을 확인,
이후 `git status`(출력 없음)와 `md5`로 원본 무변경을 이중 확인.

```
guard fired correctly: trials.json already exists and holds the preserved...
MD5 (trials.json) = 30df37c80eb78430ffa6f7778b6ab547   (변경 없음)
```

**(7) 해결 방법**: 두 출력 경로를 순회하며 존재하면 `ScoreOverwriteRefused`.
거부 메시지는 `freeze()`의 것과 같은 형태로, **같은 미결 작업**(수선 코호트는
`cohort_id`로 분리된 출력 경로가 필요하다)을 가리킨다 — 가드를 지우고
진행하는 것이 아니라 그 배선을 하라고 지시한다.

### C. I151 — 내 회귀 테스트가 필요한 명제를 검사하지 못했다 (P1 27번째)

**(5) 문제 정의**: I28의 가드는 두 경로를 **순회**하는데, 내가 쓴
`test_main_refuses_to_overwrite_the_preserved_score_file`은 이름과 달리
`SCORE_PATH` 검사를 증명하지 못했다. 루프가 `TRIALS_PATH`를 먼저 만나 거기서
raise하므로, **`SCORE_PATH`를 아예 검사하지 않는 구현으로 회귀해도 이 테스트는
통과한다.**

| | 명제 |
|---|---|
| 테스트가 실제로 검사한 것 | "존재하는 출력 파일이 하나라도 있으면 거부한다" |
| 이름이 주장한 것 | "`SCORE_PATH`가 존재하면 거부한다" |

**(6) 가설/검증**: 운 좋게 `pytest.raises(match="h1a_cohort_score.json")`가
실제 메시지(`trials.json ...`)와 불일치해 **테스트가 실패했다.** match를
느슨하게 썼다면 조용히 통과했을 것 — 즉 이걸 잡은 건 규율이 아니라
**우연히 좁게 쓴 match 패턴**이다.

**(7) 해결 방법**: `monkeypatch`로 `TRIALS_PATH`를 존재하지 않는 tmp 경로로
돌려 **`SCORE_PATH` 경로를 격리**한 뒤 거부를 확인. 이제 `SCORE_PATH` 검사를
지우면 이 테스트가 실패한다.

> **일반화**: 가드가 **여러 대상을 순회**하면, 각 대상마다 **다른 대상을
> 무력화한 상태에서** 발동을 확인해야 한다. 그렇게 하지 않으면 N개 대상 중
> 1개만 검사하는 구현과 관측값이 같다. 이건 `test_guard_negative_coverage.py`
> 가 원리상 못 잡는 층위다(그 게이트는 "음성 테스트 존재"만 본다).

### D. I150 — 운영 로그 지시의 시점 낙후 (P-문서가계약을가르침 13번째)

**(5) 문제 정의**: 2026-08-06 로그 §5 "다음 행동"이 **"운영 세션이 고칠 것 —
먼저 한다"** 로 F5(M4 ceiling을 `_h1a_score.py`에 배선)를 지시했다. 그러나
같은 날 도착한 D-H1a-13의 Q13.3이 **그 ceiling 조건 자체를 폐기**했다
(`same_modal_behavior_rule: withdrawn`). 로그는 갱신되지 않았다.

**작성 시점에 로그는 틀리지 않았다.** 판정이 나중에 그 지시를 무효화했고,
문서가 그것을 모른다 — 모순이 아니라 **supersession lag**이다.

**(6) 가설/검증**: 착수 전 D-H1a-13 전문을 읽고 F5의 대상 조건이 §6(Q13.3)에서
어떻게 처리됐는지 직접 확인:

```
Q13_3:
  same_modal_behavior_rule: withdrawn
  restore_old_anchor_cells: false
```

**(7) 해결 방법 — 이번 건은 회피했으나 절차로 고정되지 않았다.** 이번엔
"판정문을 먼저 읽자"는 판단이 우연히 작동했을 뿐이다. 일반 절차로 만들려면:

> **운영 로그의 "다음 행동"을 실행하기 전에, 그 항목을 지배하는 최신 판정문의
> 최종 명령 블록(`# 13. 최종 명령` 류)에서 그 항목이 `withdrawn` /
> `not_required` / `superseded`로 처리됐는지 확인한다.**

`NEXT_SESSION_TRAPS.md`에 등재할 후보다(미등재 — 다음 세션 작업).

### I148 — 설정돼 있고 기동도 되는데 세션에 없다

```
.mcp.json                       -> vault-retrieval 등록됨
서버 직접 구동                    -> 정상(stdio 대기, stderr 없음)
ToolSearch "vault_search"        -> No matching deferred tools found
세션 재시작 후                    -> mcp__vault-retrieval__vault_search 사용 가능
```

**"설정 존재 = 사용 가능"이 아니다.** 이 세션은 그 사실을 모른 채 skill을
호출했고(skill은 로드됐으나 그 안의 도구가 없었다), 도구가 없다는 것을
`ToolSearch` 실패로만 알 수 있었다. **원인은 미규명** — 재시작이 왜 해소했는지
확인하지 않았다.

**다음 세션에 대한 함의**: 검색 skill이 지시하는 도구가 실제로 로드돼 있는지
**먼저 확인**하고, 없으면 "rg-only"라고 명시하라(워크스페이스 `CLAUDE.md`가
이미 요구하는 규약이다 — 이번에 그 규약이 필요한 상황이 실제로 발생했다).

### I149 — 검색 도구의 출력을 직접 읽을 수 없다

`vault_search` 1회 호출이 **54,014자**를 반환해 파일로 저장됐다. 결과를 쓰려면
`jq`로 구조를 탐침하고 슬라이스해야 한다. 검색은 성공했고(`status: complete`,
40경로) 실제로 이 worktree에서 내가 모르던 문서(`PREREGISTRATION_TYPED_SCOPE_COHORT.md`,
`OPERATIONS_LOG.md`)와 다른 worktree(`concept-gate-codex-mcp-wt`)를 찾아줬다 —
**도구는 유용했고 소비 경로가 불편했다.**

### I152 — 지시 대상 오식별

사용자의 "해당 MCP를 다른 local workspace에서 사용"을 `vault-retrieval`로
읽고 venv 설치 범위를 답했다. 사용자가 뜻한 것은 **본실험 산출물인 Render
배포 concept-gate MCP**였다. 정정 후 `render.yaml`을 읽어 답이 완전히
달라졌다 — Docker 배포라 owlready2·JRE는 이미 컨테이너 안에 있고, 다른
workspace는 URL+토큰만 등록하면 되며 **로컬 설치가 아예 불필요**하다.

**교훈**: 이 워크스페이스에는 MCP가 최소 셋(`vault-retrieval`,
`evidence-vault-mcp`, 배포된 `conceptgate-mcp`) 있다. "그 MCP"라는 지시어는
**선행사가 모호하다** — 공교롭게도 이 실험이 측정 중인 결함(dangling
reference)과 같은 형태다.

## 이 회고가 남기는 방법론적 사실

**1. 이 세션은 P1을 고치러 와서 P1을 하나 더 냈다(I151).** 다만 이번 것은
**테스트가 실패해서** 즉시 드러났고, 그 이유는 규율이 아니라 우연히 좁게 쓴
`match` 패턴이었다. 좁은 assertion이 넓은 것보다 정보량이 많다는 실측 증거다.

**2. 순회하는 가드는 대상마다 격리 검증이 필요하다** — 새 하위 규칙으로
등재할 만하다. 기존 음성-테스트 커버리지 게이트는 "음성 테스트가 있는가"만
보므로 이 층위를 원리상 못 본다.

**3. 로그의 "다음 행동"은 판정 대조 없이 실행하면 안 된다(I150).** 이번엔
F5가 죽은 코드가 될 뻔했다. 문서-코드 모순이 아니라 문서-판정 시점차라
기존 탐지 방법으로는 안 잡힌다.

**4. 이슈 번호를 이어 쓰기 전에 전 worktree를 검색해야 한다(I153).** 이
worktree의 최신 회고가 I29에서 끝나 있어 I30부터 쓰는 것이 자연스러워
보였으나, Codex 세션들이 이미 I147까지 썼다. **"내 worktree에서 최신"이
"전체에서 최신"이 아니다** — 여러 세션·여러 에이전트가 같은 저장소를 쓰는
구조에서 반복될 함정이다.

**5. 미완을 미완으로 남긴 것이 이 세션의 의도적 선택이다.** QF-SELECT/
QF-DEFER fixture를 합성으로 지어내면 즉시 "완료"로 보이지만, 그 fixture는
근거 검증이 생명이라 지어내는 순간 결함이 된다. **P-자기보고과장(누적 16)을
내지 않으려면 여기서 멈추는 것이 맞다.** 대신 채점기를 먼저 만들어 다음
세션이 fixture만 채우면 되게 했다.
