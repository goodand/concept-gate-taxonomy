## (5)(6)(7) 상세 — 반복 O + 해결근거 O

### A. I23 — 정책 모듈 이중 로드 (P1 10번째, **미해결**)

**(5) 문제 정의**: `_h1a_contract._fill_policy_slots`가 `_h1a_policy.py`를
`sys.modules["_h1a_contract__policy"]`로 두 번째 로드한다.

```
프롬프트 바이트                                    <- 사본 B
모든 단언·연역검사·assert_12·FREEZE 플래그          <- 사본 A
둘이 일치한다는 검사                                = 없음
```

**(6) 가설/검증**: 가설 — 테스트가 변조하는 객체와 렌더러가 읽는 객체가 다르다.
검증 ① 첫 시도에서 **제작 세션이 틀렸다**: `_h1a_policy`를 먼저 import한 상태로
확인해 사본이 없는 것을 보고 "재현 안 됨"으로 판단했다. ② 코드를 읽어 사본이
`_fill_policy_slots` **호출 시 lazy 생성**임을 확인한 뒤 `render_arm`을 실제로
돌려 재현:

```
사본 존재: True | 같은 객체: False
copy A(테스트가 변조하는 객체) 변조가 렌더에 반영: False
```

**(7) 해결 방법**: **미해결.** 두 경로 — (a) `_h1a_contract`가 재로드하지 않고
정책 모듈을 주입받게 한다, (b) 두 사본의 `DECISION_BASIS_POLICY` 동일성을
단정하는 검사를 추가한다. **이걸 고치기 전 이 세션의 모든 뮤테이션 결과는
신뢰할 수 없다** — "잡힌다"고 확인한 M1·M3·M7도 사본 A에 대한 것이었다.

### B. I24 — §10 술어가 실행 경로 밖 (P-배선 2번째, 해결)

**(5) 문제 정의**: `assert_freezable`이 `assert_licensed_path_contrast`를
호출하지 않았다. production 경로(`_h1a_cohort.build_cohort:144`)는
`assert_freezable`만 부르므로, freeze를 실제로 막는 게이트는 여전히
`deductive_check`의 `target_mechanism_contrast` — **§10 line 466이 "필요한
명제를 보장하지 못한다"고 교체 명령한 그 술어** — 에 기대고 있었고 대체
술어는 테스트에서만 돌았다.

**이 세션 초반에 제작 세션이 고친 것과 동일한 결함이다.** D-H1a-11 리뷰가
"정책 계층이 `build_cohort`에 배선 안 됨"을 지적해 고쳤는데, 한 층 위에서
같은 실수를 했다.

**(6) 가설/검증**: 리뷰어가 `grep -rn assert_licensed_path_contrast`로 호출자가
테스트뿐임을 보였고, 제작 세션이 `_h1a_cohort.py:144`를 직접 읽어 확인했다.

**(7) 해결 방법**: `assert_freezable`에 배선. V·H를 **keyword-only 필수 인자**로
만들고 모듈 기본값을 제거했다 — 기본값이 남으면 한 인자 호출이 두 fixture
사실을 조용히 인증한다. 호출부에서 `TypeError`가 나는 것으로 강제 작동을 확인.

### C. I25 — `AXES` 순회의 구조적 사각 (P1, 해결)

**(5) 문제 정의**: 12개 단언이 전부 `for axis in AXES`로 시작한다. 따라서
`DECISION_BASIS_POLICY`에 `AXES` **밖의 키**를 넣으면 어떤 단언도 방문하지
않는다. 리뷰어의 M7(`recency`를 `CARRIER_DOMAIN`으로 양 arm 금지 — 실질적
포섭 그 자체)이 167개 전부 통과했다.

**(6) 가설/검증**: 리뷰어가 M7 실행으로 통과를 보였고, 제작 세션이 수정 후
재현해 **4 failed**를 확인했다. M1(SUBAXES 재부모화)도 3 failed로 확인.

**(7) 해결 방법**: `assert_0`(표 키 집합 == `AXES`), `assert_0b`(SUBAXES
재부모화 금지 + 표적축·하위축이 `CARRIER_DOMAIN`에 담지되지 않음),
`assert_0c`(§5 state 열 고정) 신설. `assert_12`의 subaxis 루프를
`== CARRIER_Q7`에서 "Q1이 아닌 모든 forbidding carrier"로 확장.

### D. I26 — golden이 담지자 하나를 누락 (P1, 해결)

**(5) 문제 정의**: `carriers_included`에 `Q7_NON_TARGET_TIEBREAKER`가 빠져
**그 문장에 동결 바이트가 어디에도 없었다.** 리뷰어의 M2가 §8이 제거 명령한
문구를 복원했는데 통과하며 **실제 trial 표면에 도달**했다. lint가 침묵한
이유도 §8 자신이 인용한 그 누락(bare `priority`가 토큰 목록에 없음)이다.

**(6) 가설/검증**: 리뷰어가 M2로 시연. 제작 세션이 회귀 테스트를 썼는데
**그 첫 판이 wrap 때문에 no-op**이었다 — `DID NOT RAISE`로 드러나 bullet
재구성으로 고쳤다. 검사기를 쓰면서 그 검사기가 실제로 발화하는지 확인해야
한다는 규율이 여기서도 값을 했다.

**(7) 해결 방법**: Q7 포함 재동결(`amendment_history`에 이유·`at_trials: 0`)
+ M2를 회귀 테스트로 고정.

### E. I27 — 판정문 처방 문장의 선행사 소실 (P-선행사소실 2번째, **미해결**)

**(5) 문제 정의**: §4가 verbatim 처방한 *"Source evaluation is governed by the
arm-specific source-evaluation clause"*가 REMOVED arm에서 가리킬 대상이 없다
(Q1은 KEPT 전용). 더 나쁘게, §4가 의존하는 기제("Q1이 없으므로 기본허용이
적용된다")를 무너뜨린다 — 더 구체적인 지배자를 지목하므로
specific-beats-general 읽기에서 기본허용이 배제된다.

**(6) 가설/검증**: 리뷰어 주장을 그대로 받지 않고 실측:
```
KEPT:    Q1절=True   "arm-specific...clause" 참조=True
REMOVED: Q1절=False  "arm-specific...clause" 참조=True
```
판정문 line 189-191이 이 문장을 처방했음을 확인.

**(7) 해결 방법**: **운영 세션이 고칠 수 없다** — §4 문구 변경은 설계 판정.
**D-H1a-13 상신 필요.**

## 이 회고가 남기는 방법론적 사실

**P1이 10회가 됐고, 이번 3건은 전부 "가드가 있는데 잘못된 대상을 본다"의
변종이다** — 잘못된 모듈 사본(I23), 순회 범위 밖의 키(I25), 동결 목록에서
빠진 담지자(I26). 공통점은 가드의 **존재**가 아니라 가드의 **도달 범위**가
문제라는 것이고, **이건 이 세션에 만든 음성-테스트 커버리지 게이트로도 안
잡힌다** — 그 게이트는 "가드에 음성 테스트가 있는가"만 보지 "그 가드가 검사
대상 전체에 도달하는가"는 보지 않는다.

**가장 정직해야 할 부분**: 제작 세션이 사전등록 §4에 "✅ 자동" 10건을 표시했고
그중 **4건만 참**이었다. "구현했고 테스트가 통과한다"를 "그 조건이 충족됐다"로
등치한 것이 이 실험이 반복 실패한 바로 그 등치다.
