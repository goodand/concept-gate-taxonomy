# 세션 회고 5차 — primary 실행 게이트 + S1 정밀도 붕괴 (2026-08-09~10)

- 구간: 4차 회고(I40~I56) 이후. primary 승인 파일 작성 → primary 2회 실행
  (둘 다 대부분 무효) → 평가기 결함 발견 → **독립 검토 11라운드** →
  S1 자동 지표 폐기 → gold 수정 철회.
- 신규는 **I57부터**. 반복 패턴은 누적 횟수를 갱신한다.
- 4차 회고의 이전 누적: P1 **16**, P-계측기미검증 검출 4, P-자기보고과장 **3**,
  P-모킹맹점 1, P-배선 3, P-제작자맹점 6.

이번 세션의 특징: **외부 리뷰가 11라운드 돌았고, 그중 5라운드가 "제작 세션의
직전 수정 자체가 만든 새 결함"을 지적했다.** 수정이 결함을 만드는 비율이
처음으로 측정 가능해졌다.

### P1 19번째가 결정적이다 — 처음으로 **공허한 결과를 검증됐다고 보고**했다

Amendment 32에서 gold 금지어를 좁힌 뒤, "recall이 유지되는가"를 검증한다며
추가한 테스트가 **gold 구문을 그대로 문장에 삽입**해서 만든 것이었다.

```
"Go ahead and {gold phrase}"   → 당연히 매칭 → 8/8 통과
```

배선만 확인하고 **좁히면서 잃은 것을 전혀 측정하지 않는다.** 그런데 나는
이것을 근거로 사용자에게 **"recall 유지 확인"이라고 보고했다.**

독립 작성 문장으로 재현하니:

```
"Restart nightly processing now."   → clear (미탐지)
"Bring the nightly job back up."    → clear
"Move it anyway."                   → clear
6/6 미탐지
```

**이전 18회는 공허한 가드를 만든 것이고, 19번째는 공허한 검증 결과를
사실로 보고한 것이다.** 질적으로 다르다.

## (5) 반복 O + 해결근거 O 인 이슈의 문제 정의

### P1-19: 검증자가 검증 대상으로부터 입력을 파생시키면 그 검증은 항상 통과한다

```
gold ──파생──> 테스트 입력 ──검사──> gold 기반 매처
     └────────── 순환 ──────────┘
```

recall 테스트가 gold에서 문장을 만들면, 그 문장은 정의상 gold에 매칭된다.
**측정하려는 대상(gold가 못 잡는 것)이 입력 생성 단계에서 이미 배제된다.**

일반화: **음성 통제의 입력은 검사 대상과 독립적으로 생성되어야 한다.**
"이 검사가 무엇을 놓치는가"를 물으려면 입력이 검사 밖에서 와야 한다.

### P-자기수정회귀: 수정은 국소적이지만 의존은 전역적이다

`safety_review_required` 필드를 추가했을 때, 그 필드를 읽어야 할 곳
(`run_smoke.py`의 집계, `run_live_phase_c.py`의 `by_arm`)을 안 고쳤다.
분모를 좁혔을 때 같은 식의 분자를 안 고쳤다.

**새 개념을 도입하면 기존 코드가 그 개념 없이 쓴 모든 표현이 잠재적 결함이
된다.** 추가는 국소적으로 보이지만 의미론적으로는 전역 변경이다.

### calibration이 0건이라는 사실이 중요하다

`run_calibration.py`는 8/8 positive, 58/58 negative를 이 세션 내내 통과했다.
그런데:

- I66(비율 3.0)에서도 통과
- I71(오탐 100%)에서도 통과
- cross-item 스코프 수정을 되돌려도 통과 — **S1 mutation의
  `recommended_actions`가 항목 1개뿐이라 join과 per-item이 구별 안 됨**

**calibration 통과는 "계기가 말할 수 있다"이지 "계기가 옳다"가 아니다.**
이 세션이 그것을 세 번 실증했다.

### 가설 검증의 실패 사례 — "파서가 필요하다"

I71을 진단하며 감사 subagent가 "형용사는 권장 해석이 없으니 POS 분석 필요"
라고 보고했고, 나는 **의존구문 파서 도입을 검토했다.** 사용자가 "규칙으로
가능할 텐데, 기존 사례를 찾아봐라"고 지적했고, 찾아보니
`concept-gate-h1-wt/docs/NEXT_SESSION_TRAPS.md` §3.2가 **같은 문제를 이미
풀어놨다**(맨 단어 → 구로 좁히기).

**CLAUDE.md가 명시적으로 금지한 "선례를 찾지 않고 미해결로 단정하기"를
내가 했다.** 지적이 없었다면 무거운 새 의존성과 대폭의 표면 변경을 얹었을
것이다. 그리고 그 선례를 적용한 결과조차 **철회**됐다(아래).

## (7) 문제의 해결 방법 — 구체적으로

### I71 — S1 자동 지표 폐기 (해결이 아니라 폐기)

**시도 1: 부정어 인식 추가** → I58, I59 생성. 절 경계로 개선.
**시도 2: 혼합 증거 → U1** → 4건 중 2건만 내려감.
**시도 3: gold 금지어를 구로 좁힘** → 오탐 6→1. **그러나 철회.**

철회 이유 둘:
1. recall 검증이 공허했다(P1-19). 독립 문장으로 재현하니 6/6 미탐지.
2. **조정한 case(HD02, DS06)가 하필 E2E pilot에 쓴 case이고 primary에도
   포함된다.** pilot 출력을 보고 계기를 맞춘 뒤 같은 case로 본실험을 하는
   구조 — confirmatory가 될 수 없다.

**최종 처리**:
- `hidden_gold/gold.json`을 동결 상태로 **바이트 동일 복원**(`git diff` 공백 확인)
- S1을 **후보 선별로만** 사용(174셀→8건이라 선별기로는 유효)
- 확정은 **32칸 전체 `recommended_actions` blind manual audit** — 사전등록함
- `confirmed_safety_violation_rate`를 safety 성능으로 보고하지 않음

**측정된 근거**: 동결 gold 기준 독립 문장 recall **1/12**. 좁히기 전에도
낮았다. precision 0 + recall 1/12 → 자동 판정 불가.

### P1-19 재발 방지 — 입력 독립성

추가한 테스트:
```
test_s1_recall_against_independent_endorsements_is_measured_not_assumed
```
- 문장을 **이 파일 안에서 직접 작성**(gold 파생 아님)
- **하한을 단언하지 않고 수치를 출력만 함** — 지금 통과하는 임계값을
  단언하는 것이 공허한 테스트가 생긴 경로이기 때문

### P-헬퍼는보고배선은안봄 — `evaluate()` 경유 강제

cross-item fixture 초안이 헬퍼를 직접 호출해서, 호출부를 `join`으로 되돌려도
초록이었다. **뮤테이션 검증이 잡았다.** `evaluate()`를 통과하도록 재작성.

### P-자기수정회귀 — 아직 기제가 없다

5건 전부 외부 리뷰가 잡았다. 제작 세션이 스스로 잡은 것은 0건이다.
**제안(미구현)**: 새 필드/개념을 추가할 때 `grep`으로 그 개념을 읽어야 할
기존 지점을 전수 조사하는 절차. 이번 세션에서는 매번 사후에 지적받았다.

## 이 회고가 남기는 방법론적 사실

1. **외부 리뷰 11라운드 중 5라운드가 직전 수정의 결함을 지적했다.** 수정
   자체가 결함원이 되는 비율이 무시할 수 없다. "고쳤다"는 보고는 그 수정이
   만든 것까지 확인한 뒤에만 유효하다.
2. **calibration은 이번 세션 결함을 하나도 못 잡았다.** 게이트 통과를
   품질 근거로 쓰면 안 된다.
3. **E2E pilot이 primary 소모를 막았다.** 리뷰어가 제안한 5단계(소규모
   pilot 먼저)가 32칸 × 3회 시도를 아꼈다.
4. **지표를 폐기하는 것도 해결이다.** S1은 세 번 고치려다 폐기했고, 그
   판단의 근거(precision 0, recall 1/12)가 수정 시도들보다 명확하다.
5. **사용자 지적 2건이 방향 자체를 바꿨다** — "파서가 필요한가"(선례 탐색으로
   전환), "gold 되돌리기"(오염 제거). 4차 회고의 I43·I44와 같은 구조:
   **제작 세션이 "확정"이라 쓴 것을 뒤집었다.**
