# RESEARCH REQUEST — PMB의 O1 fixture source 적격성 사전 조사

- 수신자: **조사용 agent** (다른 workspace, zero context 전제 — 이 문서가
  필요한 맥락 전부다. 설계용 agent 아님)
- 발신: ConceptGate 운영 세션, 2026-08-23
- 후속 절차: 이 조사 결과가 오면 운영 세션이 2경로 교차검증 후, 적격성
  판정 자체는 별도 기준(아래 §3)으로 기계 실측한다. **조사에게 적격성
  판정을 요청하는 것이 아니다** — 접근·라이선스·형식의 사실 확인만 요청한다.

## 1. 배경 (알아야 할 최소한)

시맨틱 컴파일 실험의 수용 오라클로 쓸 **문장 단위 gold 의미 표상 corpus**가
필요하다. 이전 후보(OSU wikisem)는 기사 단위 논리식만 공개해 부적격 판정을
받았고, 외부 설계 판정(D-E2E-v1-21)이 **Parallel Meaning Bank(PMB) Gold를
후보(candidate)** 로 지정했다 — 단 자동 승격이 아니며 적격성 스캔이 선행
조건이다.

주의 — 이 프로젝트가 이미 두 번 겪은 실패를 피하라:
1. **라이선스를 정책으로 추정하지 마라.** 배포처의 명시 문구를 원문
   그대로(verbatim) 인용하라. "아마 CC-BY일 것" 류는 결과에 쓰지 마라.
   (이전 사고: 학회 정책 추정 "CC BY 4.0" → 실제 PDF는 CC-BY-NC였음)
2. **원문 철자·URL을 문자 그대로 시도하라.** 이상해 보여도 교정하지 말고
   그대로 먼저 시도한다. (이전 사고: 논문의 `/dwnload`를 `/download`로
   "교정"했다가 404 → 부재 오판)

또한 **"확인 못함"과 "없음"을 구분해서 보고하라.** 조사 환경에서 접근이
막힌 것은 BLOCKED이지 부재 판정이 아니다.

## 2. 조사 질문 (사실 확인 6건)

### R1 — 접근 경로
PMB 배포처(https://pmb.let.rug.nl/ 로 알려짐)의 현재 릴리스 목록과 최신
버전 번호. 다운로드가 (a) 직접 링크인가 (b) 등록/신청 후인가 (c) 요청
메일인가. 직접이라면 **정확한 URL**을, 등록형이라면 절차를 기록하라.

### R2 — 라이선스 (가장 중요)
데이터 릴리스 자체의 라이선스 명시 문구를 **verbatim**으로. 배포 페이지
문구, 릴리스 내 LICENSE/README 파일, 논문 표기가 서로 다르면 **셋 다**
따로 인용하라. "공개 저장소(github, 공개 push)에 파생 해시+원문 비포함
방식으로 커밋"이 아니라 **원문 문장을 repo에 담는 것**이 허용되는지가
판정 대상이므로, 재배포·상업 조건 문구가 특히 중요하다.

### R3 — 단위와 쌍
Gold 부분에서 (a) 문장 원문 텍스트와 (b) 그 문장의 형식 의미 표상이
**문장 단위로 1:1 쌍**을 이루는가? 릴리스 디렉터리 구조에서 한 문서/문장
항목이 어떤 파일들로 구성되는지 실물 예 1건(짧은 것)을 verbatim으로.
multi-sentence 문서 단위로만 표상이 있는 부분이 섞여 있다면 그 구분 방법도.

### R4 — 표상 형식
Gold 의미 표상의 형식 이름과 문법: DRS인가, SBN(Simplified Box Notation)
인가, 둘 다인가? 각 형식의 문법을 정의한 정본 문서(논문/매뉴얼)의 위치.
특히 **양화(quantification)가 표상에서 어떻게 표현되는지** 실물 조각
1~2건(발명이 아니라 릴리스에서 그대로 잘라낸 것, 단 짧게).

### R5 — 규모
최신 릴리스에서 영어 **Gold** 문서/문장 수. Silver/Bronze와의 구분 방법
(디렉터리·메타데이터 필드 등). 숫자의 출처(페이지 문구인지, 직접 센
것인지)를 명시하라.

### R6 — 양화 관련 부분집합의 존재 신호
"모든/각/어떤/대부분" 류 한정사가 든 문장이 Gold에 실재하는지 — 검색이
가능하면 예 2~3건의 문장 텍스트(표상 말고 문장만, 짧게). 불가능하면
BLOCKED로 표기하라. 이것은 규모 감이지 적격성 판정이 아니다.

## 3. 우리가 자체 실측할 것 (조사 범위 아님 — 참고용)

수령 후 운영 세션이 기계 실측하는 적격성 기준(외부 판정이 확정한 6조건):
문장 단위 1:1 쌍 / 외부 저작 오라클(우리가 표상을 만들지 않음) / 양화
scope 관련성 / 동결된 v0 constructor profile로 완전 표현 가능 / 적격 항목
≥20건 / 유일 수용 source 금지(별도 governance). R4의 문법 정본이 있어야
constructor 스캐너를 만들 수 있다 — 그래서 R4가 R6보다 중요하다.

## 4. 보고 형식

각 R항목별로: **사실 / 근거(URL·파일 경로·verbatim 인용) / 확신도 /
BLOCKED 여부**. 시도했으나 실패한 경로도 기록하라(무엇을 어떻게 시도했는지
— 부재 판정의 근거가 된다).
